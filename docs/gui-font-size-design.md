# GUI の文字サイズ調節

*   **Author:** mkto3510
*   **Status:** Draft（2026-11-26 に，第 2 回の設計レビューの指摘と決定，実機の実験の結果を反映して改訂）
*   **Date:** 2026-11-25

--------------------------------------------------------------------------------

## Overview

Paper PDF Viewer の GUI の文字サイズを，部位ごとに設定画面から調節できるようにする．対象は，メニュー，ツールバー，タブ，目次，注釈，翻訳ウィンドウ，ダイアログ，お知らせの 8 部位である．PDF の紙面の拡大・縮小とは別の機能で，その挙動は変えない．

各部位の文字サイズは，基準フォント（アプリが起動時に OS から受け取る既定の文字．確認した環境では Yu Gothic UI の 9 pt）に対する整数のパーセント（50〜300%）で持つ．実際の大きさは「基準フォント × 部位の倍率」で決まる．倍率は設定ファイル（`settings.json`）に保存し，再起動後も保ち，開いている全ウィンドウに共通で反映する．文章を読む部位（目次，注釈，翻訳ウィンドウ）は，初期値を今より大きい 130% にする．ほかの 5 部位は 100%（今のまま）とする．

8 部位を 1 回のリリース（0.2.12）で出す（R4）．困りごとは，読む 3 部位の文字の小ささである．実装の手順 1〜4 が，この 3 部位だけで出せる最小の単位である．残りの 5 部位は，読めなくなる倍率から利用者を守る仕組み（下限，ダイアログの画面への収まり，アイコンの拡大）を伴う．そのうち，メニューバーの描画は最も不確かなので，最後（手順 5b）に置き，不合格なら，メニュー部位だけを外して出す（R8，R10）．

## The Problem

論文を読むとき，利用者は PDF の紙面だけでなく，目次，注釈のカード，翻訳ウィンドウの長い文も読む．いまのアプリは文字サイズを指定せず，OS 既定（9 pt）にすべて任せている．設定画面にも文字サイズの項目がない．そのため，これらの部位の文字は小さく，読むのが負担になる（所有者の報告．測定した値ではない）．アプリ側で変える手段がない．目標は，読む 3 部位の既定を 11.5 pt（9 pt の 130%）にすることである．

次の点が，単純な「フォントを変えるだけ」の機能にならない理由である．これらを設計で扱う．

*   最上位のダイアログとメニューのポップアップには，親ウィジェットの文字サイズが継承されない（実験で確認）．
*   カードの高さ，ボタン群の高さ，ページ欄の幅などが，既定の文字を前提に固定されている．
*   倍率を極端に小さくすると，設定画面への入口（メニュー）と設定画面自身が読めなくなる．極端に大きくすると，設定画面が画面からはみ出す．

## Goals

*   設定画面の新しいタブ「文字サイズ」で，8 部位の倍率を個別に，50〜300% の整数で設定できる（メニュー部位は，R8 により外れることがある）．
*   実効サイズを「基準フォント × 部位の倍率」とする．基準フォントは，起動時に 1 回だけ取得する．
*   目次・注釈・翻訳ウィンドウの初期値を 130%，ほかの 5 部位を 100% とする．旧版の設定ファイルから更新した利用者にも，黙って適用する．
*   設定画面の各行に「初期値へ戻す」を，タブに「すべて初期値へ戻す」を置く．戻る先は新しい初期値（130% または 100%）とする．
*   各行に，実効サイズの読み取り専用の表示と，その行だけに効く見本の文字を置く（プレビューではない．Non-Goals を参照）．
*   倍率は「保存」を押したときだけ反映し，書き込みに失敗したときは何も反映しない．
*   倍率を `settings.json` に保存し，再起動後も保つ．全ウィンドウで共通にし，開いている翻訳ウィンドウにも反映する．
*   ツールバーのアイコンを，ツールバー部位の倍率に合わせて大きくする．
*   設定画面に着いて，開いて，使える状態を保つ（画面 1366×768，基準フォント 9 pt の環境で．下限に着いてもなお収まらない場合は Risks）．
    *   小さい側: ダイアログ部位とメニュー部位の実効サイズに，下限（7 pt）を掛ける．
    *   大きい側: 設定画面の文字には，設定画面が画面に収まる上限を掛ける（設定画面だけ）．
    *   メニューから届かない場合に備え，設定の項目に `Ctrl+,` を付ける（メニューを経由しない入口）．
*   文字を大きくしたときに切れる・はみ出すレイアウト（ボタン群の高さ，注釈カードの入力欄の最小高さと高さの記憶，目次の行の高さ，色ボタン，ページ欄の幅，ウィンドウの最小幅）を直す．
*   1 つの部位を変えても，ほかの部位は変わらない．メインウィンドウの本体は，どの部位にも属さない部分を含めて，ダイアログ部位を変えても動かない（R7）．
*   倍率を設定していない旧版の `settings.json` を，そのまま読み込める．旧版へ戻したときは，新しいキーが捨てられるだけで済む．

## Non-Goals

*   全体の倍率，それを変えるショートカット（Ctrl+/- 系），メニュー項目，ツールバーのボタン，全体の「戻す」（所有者の製品上の判断．Alternative A）．
*   PDF の拡大・縮小（Ctrl++，Ctrl+-，Ctrl+0，Ctrl+Shift+0）の挙動変更．
*   設定画面でのプレビュー（入力の途中で，ほかの画面の文字をその場で変えること）と，取り消しの処理．各行の見本の文字は，その行の部品だけに効くもので，これには当たらない．
*   メニュー内のアイコンの拡大（Qt のスタイルが大きさを決める）．
*   ステータスバーの新設（既存の試験 `check_chrome_notes.py` と `check_reader.py` が「無いこと」を前提にしている）．
*   OS のファイルダイアログ，ウィンドウのタイトル，`application.py` の起動時の失敗を知らせる 2 つのメッセージボックス（別のインスタンスへ渡せない場合と，待受に失敗した場合）の大きさを変えること．後者は `shutdown` のあとに出るので，基準フォントで出る．変えられない見込みの部品は，設定画面の説明に書く．ツールチップは，アプリ全体のフォントに従う（実機の Windows 11 で確認済み）．
*   Qt が内部で作る右クリックメニュー（入力欄，選択できるラベル，`QInputDialog` の内蔵の入力欄，数値の入力欄，編集できるコンボボックス）の大きさを，メニュー部位に従わせること．これらはダイアログ部位に従う（R1）．
*   アプリ全体を拡大する `QT_SCALE_FACTOR` 方式．
*   保存済みの翻訳ウィンドウの大きさ（`dialogSize`）を，倍率に合わせて変えること（製品上の判断．D11）．
*   設定画面以外のダイアログを，画面に収まる大きさに縮めること（R3）．

## Critical User Journeys (CUJs)

### CUJ 1: 更新しただけで，読む場所が大きくなる

*   **Given**: 旧版の `settings.json`（文字サイズのキーなし）を持つ利用者が，新版を起動する．
*   **When**: 論文を開き，目次，注釈カード，翻訳ウィンドウを見る．
*   **Then**: 3 つの部位が，今の大きさの 130% で出る．メニュー，ツールバー，タブ，お知らせ，ダイアログは今まで通り．設定ファイルは，利用者が保存するまで書き換わらない．

### CUJ 2: 設定画面で注釈の文字を 150% にする

*   **Given**: 2 つのウィンドウを開き，一方で注釈カードを選択している．翻訳ウィンドウも 1 つ開いている．
*   **When**: 一方のウィンドウで，設定画面の「文字サイズ」タブを開き，注釈を 150% にして「保存」を押す．
*   **Then**: 「保存」までは，どのウィンドウも変わらない．保存後は，開いている全ウィンドウの注釈パネルが 150% になる．カードの入力欄の最小高さ，ボタン群，カードの並びが新しい文字に合う．翻訳ウィンドウの大きさは変わらない．書き込みに失敗したときは，警告が出て，何も反映されない．
*   **受け入れ目標**: カードと入力欄は作り直さないので，カードの選択，入力中のフォーカス，カーソル位置，取り消し履歴は保たれる（実験 4 で，フォーカス，カーソル位置，取り消しの可否を確認した）．スクロール位置は，既存の `Notes.layout_cards` が基準のカードとオフセットを復元する経路で保つ．同じカードが見えたままかは未確認で，試験で確かめる．

### CUJ 3: メニューを 50% にしても，設定画面に戻れる

*   **Given**: 利用者が，メニューとダイアログを 50% にして保存した．
*   **When**: メニューバーから「設定」を開く．または，`Ctrl+,` を押す．
*   **Then**: メニューバーとダイアログの実効サイズは，倍率に関係なく下限（7 pt）より小さくならないので，メニューと設定画面を読める．翻訳設定にエラーがなければ，設定画面の「すべて初期値へ戻す」→「保存」で，全部位を新しい初期値に戻せる（R11．エラーがあるときは，エラーの出たタブで直すか，`settings.json` の文字サイズのキーを消す）．

### CUJ 4: ツールバーを 200% にする

*   **Given**: 利用者が，ツールバーを 200% にして保存した．
*   **When**: ウィンドウを開く．
*   **Then**: ツールバーのアイコンが，32 px の大きさになる．メニュー内のアイコンは 16 px のまま．ウィンドウの最小幅は，使える画面の幅を超えない．幅が足りないボタンは「その他」にたたまれる．

### CUJ 5: ダイアログを 300% にしても，設定画面を閉じずに戻せる

*   **Given**: 利用者が，ダイアログ部位を 300% にして保存した．画面は 1366×768 である．
*   **When**: `Ctrl+,` で設定画面を開く．
*   **Then**: 設定画面の文字は，画面に収まる大きさまで下がる．設定画面は画面からはみ出さず，「保存」「すべて初期値へ戻す」のボタンまで届く．メインウィンドウの本体は動かない（R7）．ほかのダイアログ（「…について」など）は，300% の文字で出るので，画面からはみ出しうる（Risks を参照）．

## Technical Plan (Architecture)

### 1. 全体の考え方と用語

既存の構成は，次のとおりである．`Application`（起動と終了．設定 `Preferences`，全ウィンドウを持つ）が，主ウィンドウ `Reader`（メニュー，タブ，操作 `Reader.action`）を作る．`Reader` は，`Header`（`chrome.py`．メニューバー，道具の行，お知らせ，幅が足りないとき道具を「その他」へたたむ `fit_tools`）と，タブごとの `DocumentPane`（目次，注釈パネル `Notes` とカード `Card`，検索パネル）を持つ．翻訳ウィンドウは `TranslationDialog` である．設定は，`load_preferences` が `settings.json` を検証して読み，`SettingsDialog.commit` が書く．

用語は，次のとおりである．

*   **部位**: 文字サイズを個別に設定する，画面の 8 つの領域．
*   **部位の根**: その部位の文字を決めるために，明示的に `setFont` する部品．子の部品は親の文字を継ぐ．
*   **基準フォント**: 起動時に 1 回だけ取る，アプリ全体の既定の文字（`QApplication.font()`）．
*   **地**: `Reader` に付ける，基準サイズの文字（R7）．どの部位の根にも属さない主ウィンドウの部品が従う．
*   **倍率**: 文字サイズの割合（%）．画面のピクセル比（DPR．アイコンの絵の解像度の話に使う）と，OS の表示倍率（125%・150% など）とは別のものである．
*   **担当**: ある部品に文字を付けるコード．決定を下す「所有者」とは別の言葉として使う．

実効サイズを「基準フォント × 部位の倍率」で決め，それを次の方法で画面に届ける．

1.  **地（R7）.** `Reader` に，基準サイズの文字を 1 回付ける．どの部位の根にも属さない主ウィンドウの部品は，これに従う．ダイアログ部位を変えても，主ウィンドウの本体は動かない．
2.  **部位の根に明示的な `setFont`.** 明示したフォントは，あとからのアプリ全体の変更に影響されない．メニュー，ツールバー，タブ，目次，注釈，翻訳ウィンドウ，お知らせの 7 部位に付ける．
3.  **アプリ全体のフォント = ダイアログ部位の倍率.** トップレベルのダイアログ，メッセージボックス，ツールチップは，これに自動で従う．親の文字は，トップレベルのウィンドウには届かないので，主ウィンドウの文字には影響されない．
4.  **メニューのポップアップは，専用クラス `AreaMenu`.** ポップアップは親から継がないので，生成時に自分でフォントを付ける．メニューバーは `AreaMenuBar`（技術計画 6）．

実験（手順 0）で確かめたこと: 親の文字サイズは，最上位のウィンドウとメニューのポップアップに届かない．`QApplication.setFont` は，新しい部品に届き，イベントループが動いているときは，明示のフォントを持たない既存の部品にも届く．実機の Windows 11（既定の文字設定）で，ツールチップ，メッセージボックス（静的とインスタンス），メニューが，`setFont` に従う．ただし，Qt の `windows11` スタイルは，メニューバーの項目の文字を，フォントを無視した固定の大きさで描く（技術計画 6）．

### 2. データ（設定ファイル）

`settings.json` に，平らな整数のキーを 8 つ足す．

| 部位の識別子 | キー | 部位 | 初期値（%） | 下限（7 pt）を掛ける |
|---|---|---|---|---|
| `menu` | `fontMenu` | メニュー（メニューバーとポップアップ） | 100 | する |
| `toolbar` | `fontToolbar` | ツールバー | 100 | しない |
| `tab` | `fontTab` | タブ | 100 | しない |
| `outline` | `fontOutline` | 目次 | 130 | しない |
| `notes` | `fontNotes` | 注釈 | 130 | しない |
| `translation` | `fontTranslation` | 翻訳ウィンドウ | 130 | しない |
| `dialog` | `fontDialog` | ダイアログ（アプリ全体のフォント） | 100 | する |
| `notice` | `fontNotice` | お知らせ | 100 | しない |

*   読み込み（`load_preferences`）では，各キーを `bounded(値, 初期値, 50, 300)` で検証する．整数以外（bool，小数，NaN，文字列，null，リスト）は初期値にする．範囲外の整数は，範囲の端にする（0 と負の値は 50，301 以上は 300）．キーがなければ初期値．入れ子の辞書は使わない．
*   メモリ上の `Preferences.data` は，8 つのキーを常に持つ（初期値を補った完全な辞書）．
*   書き出し（`Preferences.save`）では，書き出す辞書から，初期値と同じ文字サイズのキーを取り除く．メモリ上の `data` からは取り除かない．ファイルにキーがなければ，次の読み込みで初期値になるので，「初期値に戻した」ことと「一度も設定していない」ことは区別されない．これは意図した動作である（のちに初期値を変える版が，一度保存した利用者にも届く）．
*   旧版の `settings.json` はそのまま読め，旧版に戻したときは，未知のキーが捨てられるだけになる．
*   R8 が発動したときは，`fonts.AREAS` から `menu` の行を外す．`fontMenu` のキーは，読み書きしない（旧版と同じ未知のキーとして捨てる）．

### 3. 実効サイズの計算

Qt に依存しない表と計算は，`fonts.py` に置く（R2）．

```text
effective_pt(base_pt, percent, floored):
    if percent == 100 and (not floored or base_pt >= FLOOR_PT):
        return base_pt                           # 100% は基準そのまま（丸めない）
    size = base_pt * percent / 100
    if floored: size = max(size, FLOOR_PT)       # FLOOR_PT = 7.0
    return floor(size * 2 + 0.5) / 2             # 0.5 pt 刻み（半分は切り上げ．R12）
```

*   下限は入力値ではなく，実効サイズに掛ける．設定画面の読み取り専用の表示にも，同じ関数を使う．
*   丸めは 0.5 pt 刻みなので，基準 9 pt では 125〜130% がどれも 11.5 pt になる（R12）．
*   基準フォントは，起動後に，`QApplication.setFont` を呼ぶ前に，1 回だけ `QApplication.font()` から取る（`font_ui.process_base_font()`．プロセスごとに 1 回．2 回目以降は保存済みの値を返す）．ポイント指定でない（`pointSizeF() <= 0`）ときは，9.0 pt を使う．対象は Windows x64 で，基準は常にポイント指定である（実機で 9.0 pt を確認）．
*   部位に付けるフォントは，基準のコピーに，**常に `setPointSizeF()` で大きさを明示して**作る（100% でも）．実験 7 で，基準のコピーをそのまま付けただけでも，あとの `QApplication.setFont` の変更を継がないことを確かめたが，明示は，確かめていない環境への備えとして残す．
*   ツールバーのアイコンの辺は，`icon_edge(percent)` で決める（技術計画 7）．

`effective_pt` の入出力（基準 9.0 pt）:

| 倍率（%） | 下限を掛ける | 実効サイズ（pt） |
|---|---|---|
| 50 | しない | 4.5 |
| 50 | する | 7.0 |
| 100 | しない / する | 9.0 |
| 130 | しない | 11.5（11.7 を 0.5 pt 刻みに丸める） |
| 150 | しない | 13.5 |
| 225 | しない | 20.5（20.25 を半分切り上げ） |
| 300 | しない | 27.0 |

基準 12.0 pt では，50%・する → 7.0（6.0 は下限未満），78%・する → 9.5（9.36 を丸める）となる．

### 4. 反映の流れ

起動時（`Application.__init__`．どの `Reader` よりも前）:

1.  `Preferences` を作る．
2.  `font_ui.process_base_font()` で，基準フォントを取る（最初の `setFont` より前）．
3.  `AreaFonts`（基準フォントと `Preferences` を持つ）を作り，`Application.fonts` に置く．
4.  `apply_dialog_font()` を 1 回呼び，保存済みのダイアログ部位のフォントを `QApplication.setFont` で付ける．
5.  `preferences.fonts_changed` を `apply_dialog_font` につなぐ．

保存時:

```text
設定画面「保存」
   │  文字サイズのキーは，変えた行だけを，保存の時点の最新の設定に重ねる
   ▼
Preferences.save(data)
   │  書き込み失敗（OSError）→ 警告，ダイアログを開いたまま，何も反映しない（data は変わらない）
   │  成功: data を更新 → changed を出す → 文字サイズのキーが変わったときだけ fonts_changed を出す
   ▼
Preferences.fonts_changed (信号)
   ├─▶ Application.apply_dialog_font(): QApplication.setFont(ダイアログ部位のフォント)
   │                                     （起動時に先に接続するので，先に動く）
   └─▶ 各 Reader.apply_fonts():   次の 5 段階を，順に実行する（段階ごとに個別の try で隔離）
          1. 部位の根へ，明示的な setFont（技術計画 5．タブの根と，各ペインの apply_fonts）
          2. 生きている AreaMenu へ setFont（self.findChildren(AreaMenu)）
          3. ツールバーのアイコンの大きさ（setIconSize）を更新（技術計画 7）
          4. 開いている翻訳ウィンドウ（pane.annotation_dialog）へ setFont
          5. ツールバーの幅の再計算を起動（chrome.timer.start()）
```

*   信号は，文字サイズのキーが変わったときだけ出す（保存の前後の `data` を比べる）．`dialogSize` の保存など，ほかのキーの保存では出さない．
*   発火の順序は，`changed`（既存）→ `fonts_changed` とする．`changed` の購読者は 3 つある．`Reader.refresh_settings`（再ラベルとアイコンの作り直し），`Documents` の規則の更新，`Notes` の高さの記憶の消去である．これらが先に走り，そのあとに `fonts_changed` の反映が走る．高さの消去は何度走っても結果が同じ（冪等）なので，`FontChange` による消去と重なっても害はない．
*   **途中失敗**（R5）: PySide は，スロットの例外を握りつぶし，残りを実行しない．対策として，`apply_fonts` の各段階を，個別に `try` で隔離し，段階 1 と 4 では，ペイン（翻訳ウィンドウ）ごと，部品ごとにも隔離する．失敗は `traceback.print_exc()` で標準エラーに書き，次を続ける．利用者への通知はしない．配布版（ウィンドウ版）には端末がなく，失敗は誰にも見えない．失敗した部品は，次に文字サイズを変えたとき（同じ値で保存し直しても再適用されない），またはウィンドウを開き直したときまで，古いままである．
*   **再計測の仕組み**: 文字が変わると，各部品が `FontChange` の通知を受けて，自分で測り直す（技術計画 8）．`apply_fonts` が明示的に起動するのは，段階 5 のツールバーの幅の再計算だけである．実験 2 で，メニューバーの文字だけの変更は `fit_tools` に届かないと分かったので，段階 5 は必要である（道具の行の文字の変更は届く）．
*   新しく作るウィンドウ・タブ・ダイアログは，作るときに現在の設定を適用する（`Reader.__init__`，`add_tab`，`DocumentPane.__init__`，`TranslationDialog.__init__`）．
*   反映に使う信号の購読は，束縛メソッドで行い，ラムダは使わない（`WA_DeleteOnClose` のウィンドウが残らないように）．ウィンドウを閉じたあとに，購読が残らないことを試験で確かめる．
*   破棄済みの部品は，巡回の対象に入らない（`tabs.widget(i)` と `findChildren` は，生きているものだけを返す）．

### 5. 部位の根と担当

各部品の文字は，次の表の「担当」が決める．担当は 1 つだけである．

| 部位 | 根（明示的に `setFont` する部品） | 担当 | 備考 |
|---|---|---|---|
| （地） | `Reader` | `Reader.__init__`（1 回） | 基準サイズ．根を持たない主ウィンドウの部品が従う（R7） |
| メニュー | `Header.menus`（`AreaMenuBar`），すべての `AreaMenu` | メニューバー: `Header.apply_fonts`．ポップアップ: 生成時に `AreaMenu` 自身と，段階 2 | ポップアップは継承されないので，自分で付ける |
| ツールバー | `Header` の道具の行（`row`） | `Header.apply_fonts` | 検索パネルは，`chrome.search` に付け替えたあと，`row` の文字を継ぐ（隠れたタブのパネルも．実験 7）．検索の一致数も同じ |
| タブ | `tabs.tabBar()`，タブ一覧のボタン（`tab_list_button`），`TabList` | `Reader.apply_fonts`．`TabList` は，開くたびに自分で付ける | `QTabWidget` 全体には付けない（中のペインに波及するため） |
| 目次 | `pane.outline` | `DocumentPane.apply_fonts` | 行の高さは自分で測る |
| 注釈 | `pane.notes`（パネルの枠とカードの全体） | `DocumentPane.apply_fonts` | カードは遅れて作られ，親から継ぐ |
| 翻訳ウィンドウ | `TranslationDialog` | `TranslationDialog` 自身（作るとき）と，`Reader.apply_fonts` の段階 4 | 最上位なので，明示が必要 |
| ダイアログ | アプリ全体のフォント | `Application.apply_dialog_font` | トップレベルのダイアログ，メッセージボックス，ツールチップ，Qt が内部で作るメニュー |
| お知らせ | `Header.notice`，`Header.external`，`DocumentPane.lookup_notice` | `Header.apply_fonts`（`lookup_notice` は `DocumentPane.apply_fonts`） | 一時表示の通知は，表示中に変わった場合は消えるまで古いまま |

*   **どの根にも属さない部品**: 主ウィンドウ（`Reader`）の中で，上の表のどの根にも属さない部品は，地に従う．トップレベルのダイアログ（設定，「…について」，プロパティ，ショートカット一覧，`QInputDialog`）とメッセージボックス，ツールチップは，ダイアログ部位に従う．設定画面は，これに加えて，文字の上限を掛ける（技術計画 9）．
*   **漏れの検出（根の監査）**: 試験で，ダイアログ部位を他と違う値（例: 180%）にして，`Reader` の木の中の全部品のフォントが，地か，ダイアログ以外の部位の実効サイズのどれかであること（ダイアログ部位の大きさの部品が，`Reader` の木の中にないこと）を調べる．木の中にあっても，トップレベルのウィンドウとその中身（`TabList` とその中の部品，ダイアログ，メニュー）は，調べる対象から除く（実験 7 で，`TabList` が app のフォントに従う，トップレベルであることを確認した）．見つかった，根を持たない部品の一覧は，手順 3 の終わりと手順 6 の終わりに，この表に書き足す．
*   メニューバーとお知らせの担当は，`Header` にまとめる．`Reader.apply_fonts` は，タブの根（タブバー，タブ一覧のボタン）と，各ペインの `apply_fonts` と `apply_icon_size` の呼び出しだけを担当する．

### 6. `AreaMenu`，`AreaMenuBar`（メニューの漏れ防止）

*   `font_ui.py` に，`QMenu` を継ぐ `AreaMenu(fonts, parent)`，`QMenuBar` を継ぐ `AreaMenuBar(fonts, parent)` を置く．生成時に，メニュー部位のフォントを自分に付ける．`fonts` は，`Reader.fonts`（`Application.fonts`）を，`DocumentPane`，`Notes`，`Card`，`Header`，ダイアログが，それぞれ自分の持ち主をたどって渡す．
*   **アプリが自分で作る `QMenu` と `QMenuBar` は，すべて `AreaMenu`，`AreaMenuBar` で，親を付けて作る**（`Reader` の木の下に置くので，`findChildren(AreaMenu)` で見つかる）．親のない `AreaMenu` は作らない．
*   `AreaMenu.addMenu` と `AreaMenuBar.addMenu` を上書きして，文字列だけの形（`addMenu(題)`）とアイコン付きの形（`addMenu(アイコン, 題)`）でも，内部で `AreaMenu`（親は自分）を作って返す．メニューの形（`addMenu(QMenu)`）は，そのまま通す．これで，`window.py` の `menu.addMenu(self.t(*names))`，`pane.py` の `menu.addMenu(icon, label)`，`menu.addMenu(t("色", "Color"))` は，呼び出しを変えずに，`AreaMenu` を作る．
*   メニューの更新（段階 2）は，`Reader.findChildren(AreaMenu)` で，生きているメニューを集めて `setFont` する．弱参照の登録簿は持たない（R9）．
*   **Qt が内部で作るメニュー**は，ダイアログ部位に従う（R1）．入力欄（`QLineEdit`，`QTextEdit`，`QPlainTextEdit`，`QTextBrowser`）の標準の右クリック，選択できるラベル，`QInputDialog` の内蔵の入力欄，数値の入力欄，編集できるコンボボックスである．メニュー部位だけを大きくしても，これらのメニューは大きくならない．
*   **漏れの検出**: 実行時の試験で，文書を読み込んだ実際のウィンドウで，サブメニュー，右クリック，色の選択のメニューを開き，`Reader` の木の下のすべての `QMenu` が `AreaMenu` であることを確かめる（親が入力欄・ラベル・数値の入力欄の，Qt が内部で作るメニューは除く）．静的な走査は行わない．
*   **メニューバーの項目の文字（実験 1・3 で判明）**: Qt 6.12 の `windows11` スタイルは，`QMenuBar` の項目の文字を，ウィジェットのフォントにかかわらず，約 9 pt の固定の大きさで描く（レイアウトの幅は，フォントに従って広がる）．ポップアップ，ボタン，ラベル，タブバー，ツールボタン，入力欄は，フォントに従う．対策は，`AreaMenuBar` に，`QProxyStyle` の派生（`MenuBarFontStyle`）を付けることである．
    *   **適用の条件**: `QApplication.style().objectName()` が `windows11` のときだけ付ける（`windowsvista`，`Fusion` は，フォントに従うことを確かめた）．基底のスタイルは，同じ名前で新しく作る（`QProxyStyle("windows11")`．アプリのスタイルの実体は包まない．`QProxyStyle` が所有権を取るため．この方式で，実験 9 で描画を確かめた）．
    *   **描画**: `CE_MenuBarItem` を，文字なしの `QStyleOptionMenuItem` で，基底のスタイルに描かせたあと，ウィジェットのフォントで，項目の矩形の中央に，文字を `drawItemText` で描く．色は `QPalette.WindowText`（無効のときは，無効のパレット）を使う．メニュー名に `&`（ニーモニック）はないので，下線の描画は要らない．
    *   **保持**: `QWidget.setStyle` は所有権を取らないので，`AreaMenuBar` が，プロキシを属性として持つ．
    *   **確認**: 27 pt の文字が描けることと，選択中（ホバー）の背景，無効の灰色が出ることを，ダークモードで確かめた（実験 1・3・9）．手順 5b では，押下の見た目，ライトモード，Alt キーでメニューバーへ移れること，メニューバーの高さを確かめる．`windowsvista` スタイルを `QMenuBar` だけに付ける案は，ダークモードの配色にならず，文字が見えなくなったので採らない．
    *   **退路（R8）**: 5b で不合格なら，`fonts.AREAS` から `menu` の行を外す（メニューとメニューバーは 100% 固定）．`AreaMenu` は，そのときも基準フォントで作られるので，残してよい．
*   **メニューバーの高さ（実験 3 で判明）**: 実機の主ウィンドウの中で，メニューバーの高さは，メニュー部位 300% でも 32 px のままだった．このため，文字が高さからはみ出す．`Header.apply_fonts` が，メニューバーの最小の高さを，`fontMetrics().height() + 8` に設定する（9 pt では 24 px で，今の 32 px を下回るので，100% の見た目は変わらない）．

### 7. ツールバーのアイコン

*   `icons._render` は，今の 16 px × 画面のピクセル比（DPR）{1, 1.25, 1.5, 2, 3} の絵に加え，辺 `edge` が 16 より大きいときは，論理サイズが `edge` で，DPR {1, 1.25, 1.5, 2, 3} 分の絵も，同じ `QIcon` に入れる．
*   辺の長さ（`icon_edge(倍率)`）は，ツールバー部位の倍率から決める（D9）．16 px × 倍率 を，段階 16/20/24/28/32/40/48 px（16 を含めて 7 段階）のうち最も近いものに丸める．同じ距離のときは，小さい方にする．上限は 48 px．倍率が 100% 以下のときは 16 px のままにする．

| 倍率（%） | 辺（px） |
|---|---|
| 50，100，101 | 16 |
| 125，130 | 20 |
| 150 | 24 |
| 175 | 28 |
| 200 | 32 |
| 225 | 32（36 は 32 と 40 の同じ距離．小さい方） |
| 250 | 40 |
| 275 | 40（44 は 40 と 48 の同じ距離．小さい方） |
| 300 | 48 |

*   アクションとツールバーのボタンには，大きい辺の絵を含む 1 つの `QIcon` を付ける．ボタンは `setDefaultAction` でアクションのアイコンを使うので，大きい絵はアクション側の `QIcon` に入れる．ボタンには `setIconSize(辺, 辺)` を付ける．メニューのアクションは，同じ `QIcon` から，要求に合う 16 px の絵を選ぶ（実験 1．DPR 1・1.25・1.5・2 で確認）．大きい辺の絵を入れないと，ボタンは 16 px の絵を拡大して描き，ぼやける．
*   **辺の供給と作り直し**: 辺は，`AreaFonts.edge()` から，そのつど読む．アイコンは，次の既存の経路で作り直す．`Reader.refresh_settings` は，今は表示言語が変わったときだけ `build_menu` を呼ぶ．これを，「表示言語またはツールバーの辺が変わったとき」に広げる（`Reader.icon_edge` を持つ）．`build_menu` は，`Reader.action`（アクションのアイコン）と `Header.bind`（`more` のアイコン）を通して，新しい辺でアイコンを作り直す．`changed` は `fonts_changed` より先に出るので，このとき `Preferences.data` は新しい値になっている．`DocumentPane.relabel`（検索パネルのボタンのアイコン）も，`changed` のたびに走るので，新しい辺で作り直す．
*   `edge` を渡す呼び出し元は，`Reader.action`，`Header.bind`，`DocumentPane.relabel` の 3 か所である．注釈カードのボタンやコンテキストメニューのアイコンは，`edge` を渡さない（16 のまま）．
*   `apply_fonts` の段階 3 は，`setIconSize` だけを更新する（`Header.apply_icon_size`: `self.buttons` と `self.more`．`DocumentPane.apply_icon_size`: 検索パネルのボタン）．
*   記憶（`lru_cache`）のキーに `edge` を入れる．アイコンは 23 個で，同時に使う辺は 2 つ（16 とツールバーの辺）だから，色が 4 通りまでなら 23 × 4 × 2 = 184 の絵が同時に生きる．`maxsize`（240）には収まるので，変えない．`icon()` は，`edge` を位置引数で渡す（`_render(name, color, edge)`．同じ絵が別のキーにならないように）．
*   DPR 1.5 では，「16 px × 1.5 = 物理 24 px」と「24 px × 1.0 = 物理 24 px」が同じ物理サイズになるが，実機で DPR を模擬して確かめたところ（手順 0 の実験 1），メニューは論理 16 px の絵を，ボタンは要求した辺の絵を選んだ．Alternative I への切り替えは要らない．限界: `QT_SCALE_FACTOR` による模擬で，OS の表示倍率（125%・150%）そのものは試していない（Open Questions）．
*   段階の最大（48 px）を超えて表示倍率が高い画面では，拡大されてぼやけうる．これは許容する（Risks を参照）．

### 7.1 ウィンドウの最小幅

`Header.fit_tools` が出す最小幅を，使える画面の幅（`availableGeometry`．`Reader` の画面）で打ち切る．メニューバーの幅（`menu_width`）も，同じ幅で打ち切る．`MINIMUM_WIDTH`（530）は，打ち切りの対象にしない（`min(max(MINIMUM_WIDTH, menu_width, 道具の幅), 使える画面の幅)`）．

*   **実験 3 の結果（実機の Windows 11，日本語のメニュー 8 項目，基準 9 pt）**: メニューバーの必要な幅は，100% で 481 px，200% で 692 px，300% で 900 px だった．300% でも 1366 px の画面に収まるので，メニュー部位の上限を下げる必要はない．メニューバーが画面より狭くなったとき，`QMenuBar` の拡張ボタン（あふれた項目を畳むもの）が現れ，項目の一部が畳まれる（単独の `QMenuBar` で，幅 700 px・500 px で確認）．設定画面には，メニューを経由せずに `Ctrl+,` でも着ける．
*   限界: 基準が 12 pt の環境では，300% の幅は約 1200 px と見積もる（測っていない）．狭い画面では，拡張ボタンに頼る．
*   下限は小さい側を守る仕組みで，大きい側は，設定画面の文字の上限（技術計画 9）と，最小幅の打ち切りで守る．

### 8. 文字が大きくなったときのレイアウト修正

文字サイズの変更で，切れる・はみ出す箇所を直す．各部品は，文字サイズの変更の通知（`FontChange`）で自分を測り直す．測り直しは，部品の初期化が終わってから行う（必要な属性が揃っているかを調べる）．`FontChange` は，子の部品の `sizeHint` が更新される前に届く恐れがあるので，再配置は，`QTimer.singleShot(0, 部品, …)` で 1 回遅らせる．

| 部品 | 直し方 |
|---|---|
| ボタン群（`ButtonGrid`，`sidebar.py`） | 列数が同じだと高さを更新しない．`FontChange` で列数を 0 に戻して，並べ直す． |
| カードの入力欄の最小高さ（`Card.editor_minimum`，`notes.py`） | 今は生成時に，親のない入力欄の `fontMetrics` で 1 回だけ計算する．プロパティにして，入力欄をレイアウトに入れたあとの `fontMetrics` から，今の値を求める．式は今のとおり `max(66, lineSpacing × 4 + 10)`．`setFixedHeight(editor_minimum)` は，レイアウトに入れたあとに行う． |
| カードの高さの記憶（`Notes` の `heights`，`tops`） | `FontChange` で，`width_used = 0` にして `layout_timer` を起動する．既存の `layout_cards` は，幅が変わったと見て高さの記憶を消し，測り直す．カードは作り直さない．基準のカードとオフセットを復元するので，スクロール位置が保たれる見込み（試験で確かめる）．非表示のタブのペインは，既存の `showEvent` が `layout_timer` を起動するので，表示するときに並び直る． |
| 目次（`WrappingOutline`） | `FontChange` で `relayout` を起動する． |
| 色の絞り込みボタン（`Notes` の `colors`） | 25×25 の固定をやめ，`max(25, fontMetrics().height() + 5)` の正方形にする．`Notes` の `FontChange` で付け直す．9 pt では今のまま（25 px）． |
| 高さ 64 の入力ボックス（`SettingsDialog` の翻訳サービスのタブ） | `setFixedHeight(max(64, lineSpacing() × 3 + 10))` にする．設定画面の文字の上限で文字が下がると，余る（許容する）． |
| 翻訳ウィンドウの引用欄（`TranslationDialog` の `excerpt`） | 属性にして，フォームに入れたあとに，`setMaximumHeight(max(110, lineSpacing() × 5 + 10))` を付ける．`apply_font` で付け直す． |
| ページ欄（`Header.page`） | 最小を `max(42, horizontalAdvance("0000") + 16)`，最大を最小 + 12 にする．`Header.apply_fonts` で再評価する．9 pt では今のまま（42〜54）． |
| 「…について」の見出し（`AboutDialog`） | ダイアログ部位のフォントを基準に，1.5 倍の大きさを，ポイント指定で付ける（`QApplication.font().pointSizeF()` を使う）． |

*   **翻訳ウィンドウ（`TranslationDialog`）**: 文字サイズの反映による再配置で，`preferred_size`（保存する大きさ）を更新しない．既存の `self.fitting`（`fit_screen` が画面に収めるあいだに立つ印）は使い回さず，新しい属性 `self.applying_font` を使う．`self.fitting = False` の隣で，`__init__` の先頭（最初の `resize` より前）に，`False` で初期化する．`apply_font` は，`applying_font = True` にして `setFont` し，`self.layout().activate()` で再配置を同期して済ませてから，`finally` で下ろす（実験 8 で，`activate()` を呼ぶと，最小サイズに合わせたリサイズが旗の立っているあいだに届き，呼ばないと，旗を下ろしたあとに届くことを確かめた）．`resizeEvent` は，`fitting` か `applying_font` が立っているあいだは，`preferred_size` を更新しない．`__init__` では，`self.resize(self.preferred_size)` の前に，翻訳部位のフォントを付ける．
*   見た目だけの固定値（タブ幅 120〜220，サイドバーの最小 145，検索欄の幅 76〜230，区切り線，タブ一覧 420×360，「…について」640×490）は，今回は変えない．

### 9. 設定画面

*   「文字サイズ」タブを，既存のタブの最後に足す（コードがタブを番号で指しているため）．タブのページは，上にスクロール領域（8 行），下に「すべて初期値へ戻す」と，例外の説明（ファイルダイアログ，ウィンドウのタイトル，起動時のメッセージボックス，設定画面が自動で縮むこと）を置く．8 行は，`fonts.AREAS` から作る．
*   **1 行の構成**（グリッドの 1 行）: (1) 部位の名前と説明（折り返しのラベル），(2) 倍率の入力（`spin(50, 300, 値)`．単位 `%`），(3) 実効サイズの読み取り専用の表示（`11.5 pt`，`9 pt`．下限が掛かって下限に着いているときは「7 pt（下限）」），(4) その行だけに効く見本の文字，(5)「初期値 130%」のような「初期値へ戻す」ボタン．
*   見本の文字は，その行の倍率の入力欄の値に追従する（下限が掛かる部位は，下限を掛けた大きさ）．その行の部品だけに効く（ほかの画面は「保存」まで変わらない）．実効サイズの表示と見本は，保存済みの値でなく，入力欄の値で求める（`AreaFonts.font(area, percent)`，`AreaFonts.pt(area, percent)`）．
*   戻すボタンは，入力欄の値を戻すだけで，書き込みは「保存」だけが行う．
*   **保存の手順（`SettingsDialog.commit`）**: 既存の検証（言語欄と，翻訳サービスの全プロファイルの検証）を終え，既存の手順で，開いたときのコピーからほかのキーの値を作ったあと，文字サイズの 8 つのキーだけを，次のとおり決める．開いたとき（`__init__`）の値（`self.font_opened`）から変えた行は，入力欄の値にする．変えなかった行は，保存の時点の最新の設定（`self.preferences.data`）の値にする．これを `Preferences.save` に渡す．書き込みの失敗は，今の `OSError` の経路（警告を出し，ダイアログを開いたまま）を使う．
    *   約束の範囲: 「他のウィンドウの保存を戻さない」のは，文字サイズのキーだけである．ほかのキーは，今まで通り，開いたときのコピーで上書きされる（既存の性質．Risks を参照）．
    *   「変えた行」は，開いたときの値との差で決める．行を変えたあと，開いたときの値に戻すと，「変えなかった行」になり，その間に別のウィンドウが保存した値が残る（Risks を参照）．
    *   **検証との関係（R11）**: 文字サイズの保存は，既存の検証に続けて行うので，翻訳設定にエラーがあるあいだは，文字サイズも保存されない（`commit` が検証で `return` する）．エラーの出たタブへは，既存の処理で誘導される．直せば保存できる．
*   **設定画面の文字の上限（R3）**: 設定画面は，最上位のダイアログで，明示の `setFont` を付ける．`__init__` の先頭で，ダイアログ部位の実効サイズを付け，タブを作り終えたあとに，`font_ui.fit_dialog_font` を呼ぶ．この関数は，設定画面の `minimumSizeHint()` が，使える画面（親ウィンドウの `screen().availableGeometry()`）から枠の余白（親ウィンドウの `frameGeometry()` と `geometry()` の差）を引いた大きさに収まるまで，0.5 pt ずつ下げる．下限（7 pt）より下げない．最大でも 40 回（27 pt から 7 pt）で，測定していない．`resize(620, 650)` は，同じ大きさで打ち切る．この上限は，設定画面を開くときに 1 回だけ決める．開いているあいだに，ほかのウィンドウが文字サイズを保存しても，設定画面の文字は変わらない（閉じて開き直すと追従する）．
*   設定の項目に `Ctrl+,` を付ける（`Reader.action` の `preferences` に，`shortcut="Ctrl+,"`．ウィンドウ単位．翻訳ウィンドウが前面のときは働かない）．メニューを経由しない入口で，メニューが読めない・届かないときの備えである．ショートカット一覧には，自動で出る．
*   復旧の手段: 設定画面の「すべて初期値へ戻す」，`Ctrl+,`，そして，`settings.json` の文字サイズのキーを消すと初期値に戻る（README に書く）．

### 11. 影響を受ける既存の試験

*   ツールバーの不変条件を確かめる既存の試験（`check_chrome_notes.py` の幅 530/760/1180/1920 のループ）は，メニュー，ツールバー，タブ，お知らせが 100% のままなので，変わらない見込み．ページ欄とメニューバーの高さは，9 pt で今の値を保つ（技術計画 6・8）．
*   目次・注釈・翻訳ウィンドウが 130% になるので，注釈の中程度の文章の高さを確かめる試験，200 件の注釈の速度を確かめる試験，翻訳ウィンドウの大きさと画面への収まりを確かめる試験は，実行して確かめる．
*   `SettingsDialog.commit()` が文字サイズのキーを書くので，設定の保存を確かめる試験を更新する．
*   `tests/check_citations_viewport.py` は，`patch("paper_reader.pane.QMenu", RecordingMenu)` で `pane.py` の `QMenu` を差し替えている．`pane.py` が `AreaMenu` を使うようになるので，`patch("paper_reader.pane.AreaMenu", RecordingMenu)` に直す（`RecordingMenu` は `AreaMenu` を継ぎ，`(fonts, parent)` を受ける．`pane.py` は `AreaMenu` を，モジュールの先頭で import する）．
*   複数の `Application` を 1 つの `QApplication` で作る試験があるため，基準フォントの取得は，プロセスごとに 1 回にする（`font_ui.process_base_font()`）．アプリ全体のフォントは，`Application.shutdown` が基準へ戻す．`font_ui.reset_base_font()`（基準フォントの記憶を消す）は，`check_gui_fonts.py` だけが，基準を固定するために呼ぶ．
*   既存の試験の期待値の意味は緩めない．既存の試験が落ちたときは，しきい値を緩めずに，コードを直す．期待値が新しい初期値（130%）に起因して変わるときだけ，変更の理由を試験のコメントに残して，値を変える．この変更で通るか確かめていない既存の試験（`check_batch_notes`，`check_range_selection`，`check_reference_navigation`，`check_pdf_history`，`check_review_regressions`）も，実行して確かめる．130% に依存した期待で落ちたときは，その試験を変更の一覧に加える．

## Alternatives Considered

「Rejected by author」は，所有者が選んだ，または取り下げた，製品や範囲の判断である（決定の記録は，Decisions の表と，ブリーフ）．「Rejected」だけのものは，実験，コードの調査，目的との不一致に基づく技術・範囲のトレードオフである．

### Alternative A: 全体の倍率（50〜200%）を部位の倍率に掛ける

*   **Pros**: 全部位をまとめて大きくできる．ショートカット，メニュー項目，ツールバーのボタンで素早く変えられる．
*   **Cons**: PDF のズームが使っている Ctrl+/-/0 と衝突する．別のキー（Ctrl+Alt 系）は，多くの欧州配列で AltGr と同じで入力欄の文字を奪い，翻訳ウィンドウが前面のときは働かない．全体の「戻す」では，ある部位を極端に小さくして読めなくなった状態から復旧できない．倍率を連打すると保存が頻発する．開いているダイアログへのライブ反映が要る．
*   **Reason for Rejection**: Rejected by author（製品上の判断）: 部位ごとの設定だけを提供する．上の Cons は，その判断を支える技術上の理由である．

### Alternative B: アプリ全体のスタイルシートで文字サイズを指定する

*   **Pros**: 1 か所で全部品の文字を変えられる．
*   **Cons**: スタイルが `QStyleSheetStyle` に変わり，Windows の描画が変わる．全体が再描画される．`fontMetrics` が古くなるので，カードの高さの測り方に影響する．既存の `palette()` のスタイルシート 2 か所（`chrome.py`，`pane.py`）と衝突する．
*   **Reason for Rejection**: Rejected: 描画方式の変更の影響が大きく，既存の測り方と衝突する．

### Alternative C: `QT_SCALE_FACTOR` / `QT_FONT_DPI` による全体拡大

*   **Pros**: コードの変更が小さい．
*   **Cons**: 再起動が必要．PDF の紙面とアイコンまで拡大され，部位ごとの設定ができない．
*   **Reason for Rejection**: Rejected: 部位ごとに調節するという目的に合わない．

### Alternative D: ダイアログ部位を除く全部位に明示的なフォントを付け，アプリ全体のフォントは触らない（クラス別フォントを併用）

*   **Pros**: アプリ全体のフォントに依存せず，部位ごとの影響が独立する．
*   **Cons**: 静的な `QMessageBox` やツールチップに明示のフォントを付けられない．実験で，クラス指定の `QApplication.setFont(f, "QMenu")` が，新しく作るメニューに効かないと分かった（効いたのは既存のメニューだけ）．
*   **Reason for Rejection**: Rejected: 実験（2026-11-25，画面を持たない環境）で，クラス別フォントが新しい部品に届かないことを確かめた．ダイアログ部位をアプリ全体のフォントにする方式（本設計）では，メッセージボックスとツールチップが自動で従う．

### Alternative E: 各ウィジェットを登録簿に登録し，部位ごとに一括で `setFont` する（宣言的な束縛 `bind_area(widget, area)` を含む）

*   **Pros**: 明示的で，試験しやすい．適用の経路が 1 つにまとまる．
*   **Cons**: 登録を忘れた箇所は，100% のまま黙って残る．静的な `QMessageBox` と `QFileDialog` は，インスタンスに触れないので対象にできない．登録の記録と適用の順序の約束が，プロセスの状態として増える．
*   **Reason for Rejection**: Rejected: 登録漏れが黙って残る．本設計は，登録簿を持たず，「根の表」と，`Reader` の木をたどる（`findChildren`）で反映し，漏れは，根の監査と，`AreaMenu` の実行時の試験で検出する（R9）．

### Alternative F: メニューのポップアップに，作成箇所の補助関数を通す

*   **Pros**: 既存の `QMenu(...)` の置き換えが小さい．
*   **Cons**: 補助関数を通さない作成箇所が，100% のまま黙って残る．メニューバーが内部で作るサブメニューは通せない場合がある．長く存在するメニューが変更の通知を受ける仕組みが別に要る．
*   **Reason for Rejection**: Rejected by author（設計上の判断）: 専用クラス（`AreaMenu`）を選んだ．クラスに閉じるので，フォントの付け方と更新の受け方が 1 か所にまとまる．

### Alternative G: アプリ全体のイベントフィルターで，表示の直前にメニューのフォントを付ける

*   **Pros**: 置き換え漏れがなく，サブメニュー，将来のメニュー，Qt が内部で作る標準メニューも自動で対象になる．
*   **Cons**: 実機で確かめたところ（実験 6），表示イベントで `setFont` すると，最初の描画から最終の大きさで出てちらつかないが，画面の端（端から 30 px）では，メニューが小さい大きさで位置を決められ，画面の外に出て，補正されなかった．アプリ全体を通る仕組みで，`AreaMenu` と併用すると，フォントを付ける仕組みが 2 つになる．
*   **Reason for Rejection**: Rejected: 画面の端での位置のずれが，技術上の欠点である．設計上は，専用クラス（`AreaMenu`）を選んだ（所有者の判断，R1）．

### Alternative H: アイコンを大きさに応じて描く `QIconEngine` を自作する

*   **Pros**: どの大きさでも鮮明．大きさを段階に丸める必要がなく，事前に作る絵の数の問題もない．
*   **Cons**: 自作エンジンのコードが増え（描画，色づけ，複製，無効状態），既存の見た目が変わる危険がある．PySide での `QIconEngine` の継承は，確かめながら進める必要がある．
*   **Reason for Rejection**: Rejected by author（設計上の判断）: 同じ `QIcon` に大きさの違う絵を足す方式を選んだ．既存の共有の仕組みを変えない．

### Alternative I: ツールバーのボタンだけに別の大きい `QIcon` を付ける

*   **Pros**: メニューとツールバーのアイコンが，構造上完全に分かれる．
*   **Cons**: 実験で，アクションの有効・無効が切り替わるたびに，ボタンのアイコンがアクションの小さいアイコンに戻されると確認した．付け直す処理が要り，通らない経路があると壊れる．
*   **Reason for Rejection**: Rejected: 実験で再同期による上書きを確認した．また，実機で DPR 1.25・1.5・2 を模擬して，メニューのアイコンが 16 px のままであることを確かめたので，この案への切り替えは要らない．

### Alternative J: 注釈一覧と注釈を別々の部位にする

*   **Pros**: パネルの枠とカードの文字を別の大きさにできる．
*   **Cons**: カードは一覧の子で，遅れて作られる．カードを 130%，一覧を 120% にすると，パネルの見出しがその下の本文より小さくなる．設定の行が 1 つ増える．
*   **Reason for Rejection**: Rejected by author（範囲の判断）: 利用者はどちらも読むので，1 つにまとめた．

### Alternative K: 設定画面で倍率をその場で反映する（プレビュー）と，取り消しの処理

*   **Pros**: 結果を見ながら調節できる．
*   **Cons**: 設定画面自体が大きさを変えるので，操作中に画面が動く．取り消し（キャンセル）で元に戻す処理が要る．
*   **Reason for Rejection**: Rejected by author（製品上の判断）: 「保存」を押したときだけ反映する．代わりに，各行に，その行だけに効く見本の文字を置く．

### Alternative L: 倍率をポイント数（pt）で保存する

*   **Pros**: 利用者が数字の意味を直感的に分かる．
*   **Cons**: PC や OS の文字設定が違うと同じ数字の見た目が変わる．データフォルダを別の PC に移したときに破綻しうる．
*   **Reason for Rejection**: Rejected: 基準フォントに対するパーセントで持つほうが，PC・OS の設定の違いに強い．実効サイズ（pt）は，設定画面に読み取り専用で出す．

### Alternative M: 保存済みの翻訳ウィンドウの大きさ（`dialogSize`）を倍率に合わせて変える

*   **Pros**: 更新直後も，最初から窮屈にならない．
*   **Cons**: 「大きさが初期値のままか」の判定と，「サイズを戻す」ボタンの戻し先の決め直しが要る．利用者が調整した大きさを変えるおそれがある．
*   **Reason for Rejection**: Rejected by author（製品上の判断．D11）: そのままにする．中身はスクロール領域にあるので，切れずにスクロールになる．

### Alternative N: コードを変えずに，OS の「テキストのサイズ」に任せる

*   **Pros**: コードの変更がない．
*   **Cons**: 部位ごとの設定にならない．OS の設定が Qt のウィジェットの文字に効くかは，確かめていない（Open Questions）．
*   **Reason for Rejection**: Rejected: 部位ごとに調節するという目的に合わない．

### Alternative O: 2 回のリリースに分ける（読む 3 部位を先に出す）

*   **Pros**: 困りごとに直接答える範囲（モデル，設定画面のタブ，読む 3 部位）が，小さく出る．`AreaMenu`，下限，複数サイズのアイコンなどのリスクを，あとに回せる．`fonts.AREAS` の表から行を生成するので，第 1 回は 3 行だけ出せる．
*   **Cons**: 設計を 2 回読み，文書を 2 版で管理する手間が要る．第 1 回の設定画面と第 2 回の設定画面で，行の数が変わる．
*   **Reason for Rejection**: Rejected by author（範囲の判断）: 8 部位を 1 リリースで出す（R4）．代わりに，手順 1〜4 を最小の単位とし，メニューバー（5b）を落とせる単位にした（R8，R10）．

### Alternative P: 下限の代わりに，メニュー部位とダイアログ部位の最小値を 80% などに引き上げる

*   **Pros**: 絶対値の下限（7 pt）の関数と，設定画面の「下限」の表示が要らない．
*   **Cons**: 基準フォントが大きい環境でも，80% 未満が選べない．基準が 12 pt のとき，下限の 7 pt（約 58%）より狭い範囲しか使えない．部位ごとの最小値を，倍率の検証と設定画面の両方に持たせる必要がある．
*   **Reason for Rejection**: Rejected: 下限を「実効サイズ（pt）」で持つほうが，基準フォントの違いに左右されずに，「読めなくなる」ことを直接防げる（D1）．

## Non-Functional Requirements

*   **Rollout & Rollback**: 新しい設定キーは，旧版で未知のキーとして捨てられるだけで，旧版へ戻しても設定ファイルは壊れない．版の番号の変更で設定の形式を区別する必要はない．既定値と同じ値は書かないので，のちに既定値を変える版が，一度保存した利用者にも届く．
*   **Performance & Latency**: 文字サイズの反映は「保存」のときだけ走り，キーの連打のような高頻度の経路はない．反映で再計測するのは，注釈カードの高さ，目次，ボタン群，ツールバーの幅だけで，PDF のレンダリングや解析には触れない．メニューの生成に加わる処理は，フォントを 1 回付けるだけである．多数のタブ・注釈での反映の時間は，測定していない（Risks）．
*   **Security & Privacy**: 新しい入力は整数のパーセントだけで，読み込み時に型と範囲を検証する．外部への通信は増えない．

## Future Improvements

*   **メニュー内のアイコンの拡大**: `QProxyStyle` でスタイルの小アイコンの大きさを変える．今回は対象外．
*   **段階の上限を超える高解像度の画面**: ツールバーのアイコンが 48 px を超えて必要な場合の描画．`QIconEngine` への切り替えを検討できる．
*   **翻訳ウィンドウの保存済みの大きさを倍率に合わせる**: 更新直後の窮屈さが問題になったときに足す．
*   **部位のまとめ表示**: 8 行が多いと感じる利用者向けに，「読む場所」をまとめて変える行や，プリセット（小・標準・大）を足す．
*   **設定以外のダイアログも画面に収める**: `font_ui.fit_dialog_font` を，「…について」，プロパティ，確認の窓にも使う（はみ出しが報告されたとき）．
*   **反映の遅延適用**: 表示中のペインだけに反映し，ほかは表示するときに適用する（多数のタブでの反映が遅いと分かったとき）．
*   **反映の自己修復と起動時の初期化オプション**: 適用した値の組を `Reader` に持たせ，表示時に差があれば再適用する．起動時の `--reset-fonts` オプション．復旧は，今回は，README に書く「`settings.json` の文字サイズのキーを消す」手順で足りる．
*   **設定の差分の保存**: `Preferences.update(patch)` で，最新の設定に差分だけを重ねて保存する．`dialogSize` の保存も同じ入口を使える．文字サイズの保存を，翻訳設定の検証から切り離すこともできる（R11 を見直すとき）．
*   **設定画面の注記**: 初期値（130%）が，更新で変わったことを，設定画面に 1 度だけ示す．
*   **失敗の通知**: 反映の失敗を，`Header.notice` に 1 行で出す（R5 を見直すとき）．

## Detailed Implementation Plan

この節が，コードレベルの記述の正本である．上の仕様部は，何を，どの部位で，どう保証するかを書く．

### Target Files to Create/Modify

#### `paper_reader/fonts.py` (Create)

*   **Type / Scope**: Python モジュール．Qt に依存しない．標準ライブラリだけを import する（R2）．
*   **Proposed Changes**:
    *   `AREAS`: 8 部位の表（名前付きタプル `Area(id, key, default, floored)` の並び）．識別子は `menu`，`toolbar`，`tab`，`outline`，`notes`，`translation`，`dialog`，`notice`．キーは `fontMenu`，`fontToolbar`，`fontTab`，`fontOutline`，`fontNotes`，`fontTranslation`，`fontDialog`，`fontNotice`．初期値は 130（`outline`，`notes`，`translation`）と 100（ほか）．`floored` は `menu` と `dialog` だけ真．日本語・英語の名前と説明は，`dialogs.py` に置く．
    *   定数: `MINIMUM_PERCENT = 50`，`MAXIMUM_PERCENT = 300`，`FLOOR_PT = 7.0`，`ICON_EDGES = (16, 20, 24, 28, 32, 40, 48)`，`FALLBACK_BASE_PT = 9.0`．
    *   `effective_pt(base_pt, percent, floored)`: 技術計画 3 の関数．
    *   `icon_edge(percent)`: `ICON_EDGES` のうち，`16 × percent / 100` に最も近いものを返す．同じ距離のときは小さい方．100% 以下は 16．

#### `paper_reader/font_ui.py` (Create)

*   **Type / Scope**: Python モジュール．Qt に依存する部分を置く．`fonts` と `PySide6` だけを import する（`preferences` は import しない）．プロセス単位の状態は，基準フォントだけである（R9）．
*   **Proposed Changes**:
    *   `process_base_font()`: プロセスごとに 1 回だけ `QApplication.font()` を保存し，2 回目以降は保存済みの値を返す．`pointSizeF() <= 0` のときは `FALLBACK_BASE_PT`．`reset_base_font()`: 記憶を消す（試験用）．
    *   `AreaFonts(base, preferences)`: `Application` が 1 つ持つ．`base_font()`，`font(area, percent=None)`（基準のコピーに，`setPointSizeF(effective_pt(...))` で大きさを必ず明示する．`percent` を省くと，`preferences.data` の値），`pt(area, percent=None)`，`percent(area)`，`edge()`（`icon_edge(percent("toolbar"))`）．
    *   `AreaMenu(QMenu)`: `__init__(fonts, parent)`．生成時にメニュー部位のフォントを自分に付ける．`addMenu(...)` を上書きし，文字列だけの形とアイコン付きの形でも，内部で `AreaMenu(fonts, 自分)` を作って返す．`addMenu(QMenu)` は，そのまま通す．
    *   `AreaMenuBar(QMenuBar)`: `__init__(fonts, parent)`．`AreaMenu` と同じ `addMenu` の上書き．`MenuBarFontStyle` を付ける処理は，手順 5b で足す（`QApplication.style().objectName() == "windows11"` のときだけ．プロキシは属性として持つ）．
    *   `MenuBarFontStyle(QProxyStyle)`（手順 5b）: 基底は，同じ名前で新しく作った `windows11`．`drawControl` は，`CE_MenuBarItem` を，文字なしのオプションで基底に描かせたあと，`widget.font()` で，項目の矩形の中央に `drawItemText` で文字を描く．
